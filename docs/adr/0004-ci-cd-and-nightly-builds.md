# CI/CD Architecture and Nightly Build Distribution

To ensure pull requests and main-branch commits remain stable while providing friction-free access to installable builds for testing, we split the automation pipeline into two distinct GitHub Actions workflows: a fast CI pipeline for PRs and pushes (executing `lintDebug`, `testDebugUnitTest`, and `assembleDebug` with failure artifact preservation) and an automated Nightly CD pipeline (`cd-nightly.yml`) triggered on a daily schedule and manual dispatch. The build process parameterizes release metadata dynamically using Gradle project properties (`-PappVersionCode` and `-PappVersionName`) injected at runtime, deriving monotonic integer version codes from Unix epoch timestamps and human-readable version names tagged with the date and git commit hash (`0.1.0-nightly.<date>.<sha>`), while defaulting cleanly to static values during local development. Distributable packages are signed using the standard Android debug keystore to eliminate secret management overhead for pre-release testing and published directly to GitHub Releases as pre-releases, retaining both workflow run artifacts and published releases for 14 days before automated pruning to manage storage quotas.
